# 主要導線の最終チェックリスト

公開前、または計算・データ・画面を大きく変更した後に、利用者が実際に通る流れを確認するための手順です。
単体テストでは確認できない、画面遷移・ブラウザ保存・スマホ表示を対象にします。

詳細な年度更新の手順は`MAINTENANCE_GUIDE.md`、データ検証は`SPEC.md`と`AGENTS.md`を参照してください。

## 実施前の準備

- [ ] 普段使いの入力内容を変更しないため、シークレットウィンドウまたは別ブラウザで確認する
- [ ] PC幅とスマホ幅（幅390px程度）の両方で確認する
- [ ] `npm test`、`npm run build`を実行する
- [ ] `data/`を変更した場合は、`python scripts/validate_data.py`も実行する

## 初回利用の流れ

- [ ] トップ画面で「はじめて使う: プロフィール設定」が押せる
- [ ] プロフィール設定で、入学年度・コース・類・プログラム・学年を選んで保存できる
- [ ] 保存後、メイン画面に戻り、プロフィールの正式名称が表示される
- [ ] トップ画面に戻ると「すでに入力済み: 履修状況を続ける」からメイン画面へ進める
- [ ] 科目一覧を直接開くと、プロフィールの入学年度・プログラムが初期選択されている

## 履修状況の入力と判定

- [ ] 必修科目を「修得」「修得予定」「不合格」に切り替えられる
- [ ] 「単位取得状況を更新」を押すまで、集計・不足・審査結果が確定済みのままになっている
- [ ] 更新後、取得単位・修得予定・不合格科目・残りの必修が期待どおり変わる
- [ ] 未更新の入力がある間だけ、画面上部の追従「更新する」が表示される
- [ ] 共通単位・その他単位認定を入力した場合、取得単位と審査用単位の違いが説明どおりに表示される
- [ ] 長い選択区分や審査詳細を開き、上部追従の「閉じる」操作で閉じられる

## 科目検索と履修計画

- [ ] 科目一覧の年度・プログラム・キーワード・学年学期の絞り込みが動く
- [ ] 科目詳細に、プロフィールに合う「要件上の位置づけ」だけが表示される
- [ ] 科目詳細の「この区分をメインで見る」から、メイン画面の該当区分まで移動できる
- [ ] 学期別の修得推奨で学年・学期を選び、必修の再履修推奨・選択の再履修候補・不足区分ごとの候補を確認できる
- [ ] スマホ幅で、学期選択・更新・リセット・入れ子の追従操作が重ならずに押せる

## バックアップと復元

- [ ] メイン画面のバックアップ案内と「単位取得状況をダウンロード」が表示される
- [ ] ダウンロードしたJSONファイルが端末に保存される
- [ ] テスト用に状態を変更またはリセットした後、JSONを読み込むと履修状況・単位認定が復元され、現在のプロフィールは維持される
- [ ] 読み込み結果のメッセージが表示される

## 問い合わせ・公開後の確認

- [ ] 「このサイトについて」で、最終データ更新・非公式サイトの注意書き・問い合わせ先を確認できる
- [ ] 不具合報告テンプレートをコピーできる。コピー不可の環境でも、テキストを選択して手動コピーできる
- [ ] 公開後はGitHub PagesのURLを開き、トップ・プロフィール設定・メイン・科目一覧・このサイトについてを一度ずつ表示する

## 記録

確認したら、プルリクエスト・コミット・`PROGRESS_LOG.md`のいずれかに次を残します。

- 実施日
- 確認した年度・コース・類・プログラム
- PC・スマホ幅での確認結果
- 見つかった不具合と、その対応状況
