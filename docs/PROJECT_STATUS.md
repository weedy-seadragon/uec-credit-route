# プロジェクトの現在地

最終更新: 2026-09-14  
開発ブランチ: `dev`  
公開ブランチ: `main`（Ver.1.0.0を公開済み）

この文書は、現在の実装状況・運用上の注意・次の確認候補を短時間で把握するための要約です。仕様は`SPEC.md`、作業規則は`../AGENTS.md`、時系列の経緯は`PROGRESS_LOG.md`を参照してください。

## 対応している範囲

- 2021年度〜2026年度入学生向けのデータを年度ごとに切り替えられる（2021・2022年度はデザイン思考・データサイエンスプログラム新設前のため、昼間14プログラム＋夜間主課程の15課程）
- 2023年度以降は昼間コースのⅠ類・Ⅱ類・Ⅲ類の15プログラムと、夜間主課程を含む16課程に対応している
- 要件充足、共通単位への算入、2年次終了時・卒業研究着手・卒業などの審査を判定できる
- 履修状態は未履修・修得・修得見込・不合格を保存でき、修得見込を含む見込みも確認できる
- クラス情報に応じて、複数セクション科目の曜日時限とシラバスリンクを絞り込める
- 学年・学期を選んで、その学期の必修・再履修・選択区分ごとの修得推奨を確認できる
- 入力内容のダウンロード・読み込み・リセットに対応している。データはブラウザ内だけに保存される

## 現在の画面上の扱い

- 長い選択区分、共通単位、審査詳細、修得推奨の候補は、見出しが画面外にあるとき上部から閉じられる
- 昼間コースの他プログラム専門科目は独立した入れ子で表示する。他類専門科目は原則自由科目で、個別認定がある場合だけ専門科目へ算入できる
- 夜間主には類・プログラムの区分がないため、他プログラム専門科目・他類専門科目認定・前後学期の子入れ子を表示しない
- 2026年度に開講しないことが確認済みの科目は、シラバスリンクを残しつつ科目名の横に注記する
- シラバスの単一の前学期／後学期が確認できる科目は、学修要覧側の学期が空欄でも学期を補完する。年次は推測しない
- 科目詳細の「要件上の位置づけ」は、プロフィールで選んだプログラムだけを表示する。プログラム未選択なら、選んだ類の共通要件だけを表示する
- トップ画面は「プロフィール設定」と「履修状況を続ける」の目的別入口を用意し、初回利用と継続利用を分けて案内する

## データと開講情報

- 科目マスタは2021年度用が1,309科目、2022年度用が1,310科目、2023年度用が1,362科目、2024年度用が1,396科目、2025年度用が1,399科目、2026年度用が1,395科目。要件データは2021・2022年度が各16ファイル、2023年度以降は各17ファイルある
- 卒業要件・科目表以外の学修要覧差分は、`YOURAN_2026_COMPARISON.md`（2025↔2026）・`YOURAN_2024_COMPARISON.md`（2024↔2025）・`YOURAN_2023_COMPARISON.md`（2023↔2024）・`YOURAN_2022_COMPARISON.md`（2021↔2022↔2024）・`YOURAN_2021_COMPARISON.md`（2021↔2022のⅡ類・Ⅲ類・夜間主）に記録している。2022〜2026年度の要件ファイルが入学年度の原本と食い違っていないかの横断チェックは`YOURAN_CROSS_YEAR_AUDIT.md`に記録している
- 2021〜2026年度すべてでⅠ類・Ⅱ類・Ⅲ類・夜間主を学修要覧原本と画像照合済み（2026-09-15時点）。2021〜2023年度データはCodeXが追加したもので、「前年度・翌年度と同一」という誤った前提を各所に含んでいたため、いずれも照合の過程で実際に差分が見つかり修正した。特に2022年度は、デザイン思考・データサイエンスがまだ無いためⅡ類・Ⅲ類・夜間主のプログラム記号自体が2024年度より1つ若い（セキュリティ情報学はf→e、機械システムはk→j等）という構造レベルの誤りだった（`YOURAN_2022_COMPARISON.md`参照）。2021年度のⅡ類・Ⅲ類・夜間主は2022年度データを土台にしているため多くの誤りを引き継いで自動修正できたが、電子工学・物理工学の科目番号や夜間主の科目入れ替わりなど2021年度固有の差分も追加で見つかっている（`YOURAN_2021_COMPARISON.md`参照）
- 曜日時限・担当教員・シラバスURLは、原則として2026年度の公式シラバスを参照する
- クラス別の対応表は`data/timetable/class_assignment_filled.csv`から`class_assignment.json`へ変換済みで、未記入の`class_id`はない

## 開発・確認手順

通常の変更後は、次を実行する。

```text

npm run lint
npm run build
```

`data/`を変更した場合は、さらに`python scripts/validate_data.py`を実行する。データ生成の順序と、`gen_data.py`実行後に`offerings`を再取得する必要がある理由は、`../CODEX.md`を参照する。

## 次の確認候補

次の未修正課題は、正式リリース後に報告される計算・開講情報・表示の不具合と優先度を比較しながら対応する。

### データ検証待ち（2026-09-15更新）

- 【中・要開発者本人の目視】セキュリティ情報学「マルチメディア処理」の2021年度の科目番号を、`data/subjects/youran-2021.json`のCOM507eのまま据え置いた判断の裏取り。2021年度原本はこの科目を「データベース論」と同じ番号（COM506e）で印字しているが、2022年度以降は明確に別番号（データベース論=COM506e、マルチメディア処理=COM507e）で印字されている。他プログラム（情報通信工学・電子情報学）は2021・2022年度どちらの原本でも一貫していた（`YOURAN_CROSS_YEAR_AUDIT.md`⑥参照）ため2022年度以降の値へ統一する根拠があったが、セキュリティ情報学は2021年度だけが重複という非対称なパターンで、「2021年度原本側の印刷ミス」と推測して現状維持にしたに過ぎず確証はない。`PDF/youran2021.pdf`のC.3.2セキュリティ情報学プログラムのページ（自由科目区分、31〜32ページ付近）と`PDF/youran2022.pdf`の同じ箇所を開発者自身の目で見比べて、本当に2021年度側の誤植なのか、それとも2021年度当時は実際にこの2科目が同一番号を共有する運用だったのかを判断してほしい
- 【中】電子情報学「情報通信と符号化」（ELE403h）は、2026-09-15まで科目名が別科目「基礎情報通信」と誤登録されていた。名前は修正済みだが、`offerings`（曜日時限・担当教員・シラバスURL）は誤った科目名でシラバス取得されていた可能性があるため、次回`fetch_syllabus.py`をフル実行する際に正しく再取得できているか確認する（`YOURAN_2021_COMPARISON.md`参照）
- 【中】バックアップ読み込み時に、保存されたプロフィールと現在の入学年度・昼夜・類・プログラムの不一致を検出し、誤った要件データへ履修記録を合流しないようにする。
- 【中】時間割データの未対応クラス表記（「留学生」「留学生のみ」「上級者」）と、現在のプログラム名と一致しない表記（「経営社会情報学プログラム」「電気情報学プログラム」）の扱いを決める。
- 【中】読み込みJSONの科目番号・履修状態・その他認定単位を実行時に検証し、不正な値や範囲外の数値で集計が壊れないようにする。

- クラス情報が不足する場合の曜日時限・シラバスリンクの案内を、実例に合わせて改善する
- 公式シラバスと科目マスタの名称差により開講情報を取得できない科目を、必要時に個別確認する
- 学期別の修得推奨が、実際の履修計画に十分役立つかを利用者の意見とともに確認する
- WebMCPによるエージェント操作対応を検討する。対応ブラウザの成熟度、公開する操作の範囲、プロフィール・履修状況などブラウザ内データの読み取り／変更時の確認方法を設計してから着手する

## 科目の同一視に関する確定方針

- 通常科目は、科目名が同じなら同一科目として扱ってよい。人間が確認した対応だけを`aliases.json`へ列挙する方式への変更は行わない
- 再履用の授業は、同名であっても通常開講と同じセクションとして扱わない。`class_id`の「再履生」「再履全員」や再履修状態を使い、通常開講とは別に曜日時限・シラバスリンクを解決する

## 入学年度変更時の履修記録に関する確定方針

- 履修記録・その他認定単位の保存先は入学年度ごとに分けない。入学年度を間違えて設定した利用者が年度だけを訂正しても、入力済みの履修記録をそのまま引き継げることを優先する
- 入学年度を変更した後は、保存済みの科目番号を変更後の年度の科目マスタで解釈する
