# プロジェクトの現在地

最終更新: 2026-09-14  
開発ブランチ: `dev`  
公開ブランチ: `main`（Ver.1.0.0を公開済み）

この文書は、現在の実装状況・運用上の注意・次の確認候補を短時間で把握するための要約です。仕様は`SPEC.md`、作業規則は`../AGENTS.md`、時系列の経緯は`PROGRESS_LOG.md`を参照してください。

## 対応している範囲

- 2021年度〜2026年度入学生向けのデータを年度ごとに切り替えられる（2021・2022年度はデザイン思考・データサイエンスプログラム新設前のため、昼間14プログラム＋夜間主課程の15課程）
- 2023年度以降は昼間コースのⅠ類・Ⅱ類・Ⅲ類の15プログラムと、夜間主課程を含む16課程に対応している
- 要件充足、共通単位への算入、2年次終了時・卒業研究着手・卒業などの審査を判定できる
- 履修状態は未履修・修得・修得見込・不合格を保存でき、修得見込を含む見込みも確認できる
- クラス情報に応じて、複数セクション科目の曜日時限とシラバスリンクを絞り込める
- 学年・学期を選んで、その学期の必修・再履修・選択区分ごとの修得推奨を確認できる
- 入力内容のダウンロード・読み込み・リセットに対応している。データはブラウザ内だけに保存される

## 現在の画面上の扱い

- 長い選択区分、共通単位、審査詳細、修得推奨の候補は、見出しが画面外にあるとき上部から閉じられる
- 昼間コースの他プログラム専門科目は独立した入れ子で表示する。他類専門科目は原則自由科目で、個別認定がある場合だけ専門科目へ算入できる
- 夜間主には類・プログラムの区分がないため、他プログラム専門科目・他類専門科目認定・前後学期の子入れ子を表示しない
- 2026年度に開講しないことが確認済みの科目は、シラバスリンクを残しつつ科目名の横に注記する
- シラバスの単一の前学期／後学期が確認できる科目は、学修要覧側の学期が空欄でも学期を補完する。年次は推測しない
- 科目詳細の「要件上の位置づけ」は、プロフィールで選んだプログラムだけを表示する。プログラム未選択なら、選んだ類の共通要件だけを表示する
- トップ画面は「プロフィール設定」と「履修状況を続ける」の目的別入口を用意し、初回利用と継続利用を分けて案内する

## データと開講情報

- 科目マスタは2021年度用が1,312科目、2022年度用が1,313科目、2023年度用が1,356科目、2024年度用が1,390科目、2025年度用が1,396科目、2026年度用が1,392科目。要件データは2021・2022年度が各16ファイル、2023年度以降は各17ファイルある
- 卒業要件・科目表以外の学修要覧差分は、`YOURAN_2026_COMPARISON.md`（2025↔2026）・`YOURAN_2024_COMPARISON.md`（2024↔2025）・`YOURAN_2023_COMPARISON.md`（2023↔2024）・`YOURAN_2022_COMPARISON.md`（2021↔2022↔2024）に記録している
- **2021年度のⅡ類・Ⅲ類・夜間主、および2022年度のⅢ類・夜間主はPDF画像で照合済みではない**（2026-09-14時点）。2021〜2023年度データはCodeXが追加したもので、「前年度・翌年度と同一」という誤った前提を各所に含んでいた。2023年度は昼間15プログラム＋夜間主の16課程すべて、2022年度はⅠ類4プログラム・Ⅱ類5プログラム、2021年度はⅠ類4プログラムを画像照合済みで、いずれも実際に差分が見つかり修正した。特に2022年度は、デザイン思考・データサイエンスがまだ無いためⅡ類のプログラム記号自体が2024年度より1つ若い（セキュリティ情報学はf→e等）という構造レベルの誤りだった（`YOURAN_2022_COMPARISON.md`参照）。2021年度は2022年度データを土台にしているため多くの誤りを引き継いで自動修正できたが、Ⅱ類・Ⅲ類・夜間主自体はまだ照合していないため、これらの数値を鵜呑みにしない
- 曜日時限・担当教員・シラバスURLは、原則として2026年度の公式シラバスを参照する
- クラス別の対応表は`data/timetable/class_assignment_filled.csv`から`class_assignment.json`へ変換済みで、未記入の`class_id`はない

## 開発・確認手順

通常の変更後は、次を実行する。

```text
npm test
npm run lint
npm run build
```

`data/`を変更した場合は、さらに`python scripts/validate_data.py`を実行する。データ生成の順序と、`gen_data.py`実行後に`offerings`を再取得する必要がある理由は、`../CODEX.md`を参照する。

## 次の確認候補

次の未修正課題は、正式リリース後に報告される計算・開講情報・表示の不具合と優先度を比較しながら対応する。

### データ検証待ち（2026-09-14、最優先）

- 【高】**2021年度のⅡ類・Ⅲ類・夜間主、および2022年度のⅢ類5・夜間主が、学修要覧PDFで画像照合されていない。** 2023年度は全16課程、2022年度はⅠ類4・Ⅱ類5プログラム、2021年度はⅠ類4プログラムを2026-09-14に画像照合済みで、いずれも実際に差分が見つかり修正した（`YOURAN_2023_COMPARISON.md`・`YOURAN_2022_COMPARISON.md`参照）。2022年度は特に、デザイン思考・データサイエンスがまだ無いためⅡ類のプログラム記号自体が2024年度より1つ若い（セキュリティ情報学はf→e等）という構造レベルの誤りだった。これらはCodeXが「前年度・翌年度と同一」という前提で複製したもの。`validate_data.py`の自動チェックは科目の必修/選択/自由の区分違いや、プログラム記号のずれのように「科目マスタとの整合性はあるが実体が別科目」という種類のバグを検出できないため、2021年度のⅡ類・Ⅲ類・夜間主、2022年度のⅢ類・夜間主にも同種の誤りが残っている可能性が高い。手順は`docs/PDF_READING_NOTES.md`・`YOURAN_2023_COMPARISON.md`・`YOURAN_2022_COMPARISON.md`の方法を踏襲する
- 【低】**セキュリティ情報学・情報通信工学・電子情報学の「マルチメディア処理」の科目番号に食い違いの疑いがある。** 2021・2022年度の学修要覧原本の画像表記（セキュリティ情報学COM506x/507x、情報通信工学・電子情報学ELE505x/506x）と、現在の科目マスタの値（COM507x等）が一致しない箇所を2026-09-14に発見したが、原本側の表記揺れか既存データ側の誤りかを切り分けられず判断を保留した（`YOURAN_2022_COMPARISON.md`参照）。影響は自由科目1件の科目番号のみで卒業要件の判定には影響しない
- 【中】**2024年度データに2件の見落としがある**：①Ⅲ類光工学プログラムの「画像情報学基礎」（ELEa02n）は学修要覧2024の原本に実在しないが、現在の2024年度データには残っている（`YOURAN_2024_COMPARISON.md`の2024↔2025照合で見落とされていた）。②Ⅱ類計測制御システム・先端ロボティクスの大学院連携科目「Advanced Robotics and Mechatronics Engineering」（MCEb13i等）は、2025年度新設と誤認されて2024年度データから除かれているが、2022年度の時点で既に存在していた科目（`YOURAN_2022_COMPARISON.md`参照）。いずれも2026-09-14に2023・2022年度の照合中に副次的に発見したもので、今回はその年度のデータ修正が目的のため2024年度データ自体の修正は未着手
- 【中】バックアップ読み込み時に、保存されたプロフィールと現在の入学年度・昼夜・類・プログラムの不一致を検出し、誤った要件データへ履修記録を合流しないようにする。
- 【中】時間割データの未対応クラス表記（「留学生」「留学生のみ」「上級者」）と、現在のプログラム名と一致しない表記（「経営社会情報学プログラム」「電気情報学プログラム」）の扱いを決める。
- 【中】読み込みJSONの科目番号・履修状態・その他認定単位を実行時に検証し、不正な値や範囲外の数値で集計が壊れないようにする。

- クラス情報が不足する場合の曜日時限・シラバスリンクの案内を、実例に合わせて改善する
- 公式シラバスと科目マスタの名称差により開講情報を取得できない科目を、必要時に個別確認する
- 学期別の修得推奨が、実際の履修計画に十分役立つかを利用者の意見とともに確認する
- WebMCPによるエージェント操作対応を検討する。対応ブラウザの成熟度、公開する操作の範囲、プロフィール・履修状況などブラウザ内データの読み取り／変更時の確認方法を設計してから着手する

### 運用上の注意（複数セッション併用時）

- 2026-09-13〜14にかけて、このドキュメントや`requirementSets.ts`等がこのセッションの外（CodeX）でも並行して更新されていた。同じ`dev`ブランチを複数のAIセッションで同時に触ると、片方が前提にしたファイルをもう片方が知らないまま更新してしまうリスクがある。並行作業させる場合は、作業前に`git fetch`で最新化し、担当範囲（ファイル・機能）を分けることが望ましい

## 科目の同一視に関する確定方針

- 通常科目は、科目名が同じなら同一科目として扱ってよい。人間が確認した対応だけを`aliases.json`へ列挙する方式への変更は行わない
- 再履用の授業は、同名であっても通常開講と同じセクションとして扱わない。`class_id`の「再履生」「再履全員」や再履修状態を使い、通常開講とは別に曜日時限・シラバスリンクを解決する

## 入学年度変更時の履修記録に関する確定方針

- 履修記録・その他認定単位の保存先は入学年度ごとに分けない。入学年度を間違えて設定した利用者が年度だけを訂正しても、入力済みの履修記録をそのまま引き継げることを優先する
- 入学年度を変更した後は、保存済みの科目番号を変更後の年度の科目マスタで解釈する
